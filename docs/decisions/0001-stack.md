# 0001: Stack (Hono + Postgres preset)

- Date: set by /kickoff
- Status: accepted

## Context
The project was installed with the harness-kit `hono-postgres` preset, so the stack is decided before /kickoff.

## Decision
- TypeScript on Node, run with `tsx` (no build step). HTTP with Hono on `@hono/node-server`.
- Contract first in code: routes are `@hono/zod-openapi` `createRoute`s with zod schemas; `openapi.json` is generated and committed.
- Postgres with Drizzle ORM (`postgres` driver); migrations generated by `drizzle-kit` in `drizzle/`. A Postgres 17 container per project on a free port (`scripts/db-up.sh`), locally and in CI.
- Tests: Vitest calling the app in-process, every response checked against `openapi.json` (Ajv); coverage thresholds.
- Gates beyond tests: ESLint, `tsc`, jscpd, dependency-cruiser, `npm audit`, Semgrep, migration lint, schema and contract drift, a latency budget (autocannon) in CI.

## Consequences
- Every worktree and loop lane shares one local database, so tests never reset it (golden principle 7).
- A route change is not done until `openapi.json` is regenerated; clients and reviewers see the contract change in the diff.
- Hosting is left to a later decision; the API is a plain Node process reading `DATABASE_URL` and `PORT`.
