# Design M1: accounts with bearer tokens, private bookmarks, read status and cursor pagination

Builds on `docs/decisions/0001`–`0004`. Where this doc and 0003 differ, 0004 explains why.

## Features
- F001 sign-up: `users` + `tokens` tables, password and token hashing in `lib/auth`, error envelope, validation hook and `onError` (malformed JSON → 400 naming `body`, anything else → 500 `internal_error`) in `lib/errors`, registered in `src/app.ts`.
- F002 sign-in: same tables; constant-work credential check.
- F003 `GET /me`: the `requireAuth` middleware every protected route uses, and the `bearerAuth` security scheme.
- F004 sign-out: `tokens.revoked_at`.
- F005 unknown routes: `app.notFound` in `src/app.ts`, via `lib/errors` (`onError` already exists from F001).
- F006 save: `bookmarks` table, `Bookmark` schema, `lib/bookmarks.create`.
- F007 duplicate url: unique index on `(user_id, md5(url))`, 409 body with `existing_id`.
- F008 get one: owner-scoped lookup, non-UUID id is 404.
- F009 list: `lib/pagination` (limit, cursor) and the `(user_id, created_at desc, id desc)` index.
- F010 edit, F011 delete: owner-scoped update/delete.
- F012/F013 read/unread: `read_at` column.
- F014 status filter: `status` query param on the list.
- F015 contract coverage test: the per-route error responses listed under Contract.
- F016 latency budget: extends `scripts/perf.ts` and `perf.config.json` as described under NFR.

## Data model
All ids `uuid` default `gen_random_uuid()`. All timestamps `timestamptz` (microsecond precision in the DB; ISO 8601 UTC with milliseconds in JSON). Schema in `src/db/schema.ts`.

- **users**: `id` pk; `email text not null unique` (stored trimmed + lowercased, ≤254); `password_hash text not null` (scrypt, 64-byte key, hex); `password_salt text not null` (16 random bytes, hex); `created_at not null default now()`.
- **tokens**: `id` pk; `user_id → users.id on delete cascade`, indexed; `token_hash text not null unique` (SHA-256 hex of the plain token); `created_at`; `revoked_at null`. A token is valid iff its hash exists and `revoked_at is null`.
- **bookmarks**: `id` pk; `user_id → users.id on delete cascade`; `url text not null` (trimmed, ≤2048); `title text not null` (trimmed, ≤500, defaults to url); `note text null` (≤10,000); `read_at null`; `created_at`, `updated_at` not null default now().
  - `bookmarks_user_url_uq` unique on `(user_id, md5(url))`: per-user exact-string duplicates. md5 because a 2048-char non-ASCII url can exceed the btree tuple limit; the lookup for `existing_id` compares `url` itself.
  - `bookmarks_user_created_idx` on `(user_id, created_at desc, id desc)`: serves list, cursor and status filter.
- Field length limits are enforced by the zod schemas at the boundary, not by DB checks.
- Access rules (no RLS; one app role): every query on `tokens` and `bookmarks` lives in `src/lib` and takes the caller's `userId` in its `where`. Routes cannot import `src/db` (dependency-cruiser `routes-not-db`).

### Migrations
1. `drizzle/0000_*.sql`: create `users`, `tokens`, `bookmarks` with the constraints and indexes above (new tables only; rollback drops them). Built in this branch (Shared scaffold). M1 features add no further migrations.

## Contract
Generated `openapi.json` from `createRoute`s; zod schemas live next to their routes, shared schemas in `src/lib`. Error body (`ErrorSchema` in `lib/errors`): `{ error: { code, message } }`; the 409 `duplicate_url` adds `error.existing_id` (uuid). Every route documents every status below with that schema. Protected routes declare `security: [{ bearerAuth: [] }]` and `middleware: [requireAuth]` on the route itself (0002: never `app.use("/x/*")` or `mount()`).

`User = { id, email, created_at }`. `Bookmark = { id, url, title, note: string|null, read_at: string|null, tags: string[] (always [] in M1), created_at, updated_at }`. `Page<T> = { items: T[], next_cursor: string|null }`.

| Route | Auth | Body / query | Success | Errors |
|---|---|---|---|---|
| `POST /auth/sign-up` | public | `{ email, password(8–128) }` | 201 `{ user: User, token }` | 400 validation_error, 409 email_taken |
| `POST /auth/sign-in` | public | `{ email, password }` (password 1–128) | 200 `{ user, token }` | 400, 401 invalid_credentials |
| `POST /auth/sign-out` | bearer | – | 204 empty | 401 |
| `GET /me` | bearer | – | 200 `User` | 401 |
| `POST /bookmarks` | bearer | `{ url, title?, note? }` | 201 `Bookmark` | 400, 401, 409 duplicate_url |
| `GET /bookmarks` | bearer | `limit` 1–100 (default 20), `cursor`, `status` read\|unread | 200 `Page<Bookmark>` | 400 validation_error / invalid_cursor, 401 |
| `GET /bookmarks/{id}` | bearer | – | 200 `Bookmark` | 401, 404 |
| `PATCH /bookmarks/{id}` | bearer | `{ title?, note?: string\|null }` | 200 `Bookmark` | 400, 401, 404 |
| `DELETE /bookmarks/{id}` | bearer | – | 204 | 401, 404 |
| `PUT /bookmarks/{id}/read` | bearer | – | 200 `Bookmark` | 401, 404 |
| `DELETE /bookmarks/{id}/read` | bearer | – | 200 `Bookmark` | 401, 404 |
| any unknown route | – | – | – | 404 not_found |

Rules every route follows:
- Validation: each route file creates `new OpenAPIHono({ defaultHook: validationHook })`; the hook turns a zod failure into 400 `validation_error` whose message starts with the first issue's field path (e.g. `url: ...`). JSON bodies are `required: true`. Malformed JSON (Hono's 400 `HTTPException`) becomes `validation_error` naming `body` in `app.onError`; any other error is 500 `internal_error`, generic message, logged without body or headers.
- `{id}` param is `z.string()`, not `z.uuid()`: lib returns "not found" for a non-UUID, so the route answers 404 (0003).
- Order on a protected route: auth (401) → param/body validation (400) → owner lookup (404). Validation runs in the route's zod hook, which Hono runs after route middleware, so a bad body without a token is 401.
- `limit` is `z.coerce.number().int().min(1).max(100).default(20)`; `status` is `z.enum(["read","unread"]).optional()`.
- Cursor (0004): base64url JSON `{ c, i }`, `c` the last item's `created_at` at microsecond precision (`YYYY-MM-DDTHH:MM:SS.ffffffZ`), `i` its id. Decode failure or wrong shape → 400 `invalid_cursor`. Page query: `where user_id = $u [and read_at is (not) null] and (created_at, id) < ($c, $i) order by created_at desc, id desc limit $limit + 1`; `next_cursor` is set only when the extra row exists.
- `PUT …/read`: `read_at = coalesce(read_at, now())`. `DELETE …/read`: `read_at = null`. PATCH, PUT/DELETE read set `updated_at = now()`.
- POST bookmark: `insert … on conflict do nothing returning *`; when nothing returns, select the existing id by `(user_id, url)` and answer 409.

## Modules
- `src/server.ts`: starts the Node server (imports `app` and `lib/env`; exists).
- `src/app.ts`: builds the root `OpenAPIHono`, registers `bearerAuth`, mounts route apps with `app.route()`, sets `notFound`/`onError`, serves `/openapi.json`.
- `src/routes/auth.ts` (sign-up, sign-in, sign-out), `src/routes/me.ts`, `src/routes/bookmarks.ts` (all `/bookmarks` routes), `src/routes/health.ts`: HTTP only: schemas, status codes, calling lib.
- `src/lib/errors.ts`: `ErrorSchema`, `apiError(c, status, code, message, extra?)`, `validationHook`, `onError`, `notFound`.
- `src/lib/auth.ts`: scrypt hash/verify (`timingSafeEqual`), token create (32 random bytes base64url) + SHA-256, user/token queries, `requireAuth` middleware setting `c.var.userId` and `c.var.tokenId`.
- `src/lib/bookmarks.ts`: every bookmark query, each scoped by `userId`; maps rows to `Bookmark`.
- `src/lib/pagination.ts`: `limit` schema, cursor encode/decode.
- `src/lib/env.ts`: env parsing (exists).
- `src/db/schema.ts`, `src/db/client.ts`: tables and the connection.

Import rules (`.dependency-cruiser.cjs`): `app.ts` → routes, lib; `server.ts` → `app.ts`, lib; neither imports `src/db` (`app-not-db`). routes → lib only (not `src/db`, not other route files). lib → lib, db; never routes. db → `lib/env.ts` only. No cycles.

## Shared scaffold
Built in this branch: `src/db/schema.ts` with `users`, `tokens`, `bookmarks` and migration `drizzle/0000_*.sql` (every feature from F001 to F014 needs these tables; one migration avoids 0000-numbered conflicts between parallel lanes). Also the dependency-cruiser rules above. Nothing else: no routes, helpers or middleware; features build those. Features whose `touches` list `src/db/schema.ts` or `drizzle/**` should not need to change them.

## NFR
- Load: one owner, a handful of accounts; at most a few requests per second; ~1,000 bookmarks per user (perf target), notes ≤10 KB. List routes (`GET /bookmarks` default, `limit=100`, `status=read`, a cursor page) p99 < 150 ms locally with 1,000 bookmarks. F016 extends `scripts/perf.ts`: before loading, it signs up a fresh user (email unique per run, golden principle 7), seeds 1,000 bookmarks (some marked read) through the API, and sends that user's bearer token on every request; a `perf.config.json` entry may set `"auth": true` (send the token) and `"cursor": true` (fetch the first page and append `cursor=<next_cursor>` to `path`). Entries: `/bookmarks`, `/bookmarks?limit=100`, `/bookmarks?status=read`, and `/bookmarks?limit=20` with `cursor: true`, each `p99: 150`, all `auth: true`. No other route gets a latency budget in M1. Postgres pool max 5 (existing). scrypt (N=16384) costs ~50 ms per sign-up/sign-in, acceptable at this load.
- Security: attacker = anyone who can reach the port without a valid token, or another account holder. Stops: every bookmark/me/sign-out route runs `requireAuth` per route and every bookmark query filters by `user_id`, so another user's id is 404; tokens stored only as SHA-256, passwords as salted scrypt, compared in constant time; sign-in for an unknown email still runs scrypt against a dummy hash so timing does not reveal which emails exist; plain token returned once; passwords, tokens and hashes never logged or returned (only the `User` shape leaves `lib/auth`); 500s carry no SQL or stack; unsigned cursors only move within the caller's own rows. Brute force on sign-in is M2 (rate limits).
- Cost: local only: Node process plus the existing Postgres 17 Docker container. $0.

## Decisions
- Cursor timestamp at microsecond precision instead of the millisecond ISO string 0003 implies: in-process tests create rows within the same millisecond, and a millisecond cursor would skip or repeat them. Alternative rejected: `timestamp(3)` columns (ties within a ms still fall to the random uuid, so "A, B, C saved in order" could list out of order). Recorded in `docs/decisions/0004-m1-design-refinements.md`.
- Unique on `(user_id, md5(url))` instead of `(user_id, url)`: the btree tuple limit (~2.7 KB) can be exceeded by a 2048-char multibyte url and would surface as a 500. 0004.
- Routes may not import `src/db` (narrower than the preset's "routes may import lib and db"): keeps every query, and its `user_id` filter, in `src/lib` where review looks. 0004.
- One migration for all M1 tables, built before features, rather than one per feature: parallel lanes would otherwise each generate a `0000_*` migration and conflict.
- No RLS: single DB role and a single app; owner scoping in lib plus the import rule is enough for one owner, and RLS would need a per-request `set_config` on a pooled connection.
- `updated_at` maintained by the app in lib updates, not a trigger: fewer moving parts.
